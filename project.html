Student timetable app

When
Semester A, year 1
Built with
HTML, CSS, JavaScript
Role
Solo project

What it does

You enter your modules and their sessions, and the app draws a weekly grid. If two sessions overlap it highlights the clash and lists both so you can decide which to attend. Everything is stored in the browser so there is no sign-up.

What I learned

Drawing a grid that still works on a phone was harder than the logic. I ended up switching to a list view below a certain width, which is also easier for a screen reader to follow.

Bus arrivals data analysis

When
Semester B, year 1
Built with
Python, pandas, matplotlib, Jupyter
Role
Group of three, I did the cleaning and charts

What it does

Takes a month of open data on bus arrivals, removes duplicate and malformed records, and works out the average delay per route and per hour of the day. The output is a short set of charts with plain-English captions.

What I learned

Most of the time went on cleaning. Timestamps came in three formats and a few routes changed number part way through the month. Writing down every cleaning decision made the final write-up much easier to defend.

Password strength checker

When
Own time, summer
Built with
Python
Role
Solo project

What it does

A command-line tool that scores a password from 0 to 4. It checks length, character variety, keyboard patterns and whether the password appears in a list of known breached passwords. It explains each point lost so the user knows what to change.

What I learned

Explaining the score turned out to matter more than the score itself. Early testers ignored a bare number but acted on a sentence like "this is in a list of leaked passwords".
